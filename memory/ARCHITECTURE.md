# Architecture

## 1. Big picture

```text
Browser (index.html + js/bridge.js + js/api.js + css/)
   │  user clicks → StarAppBridge.dispatchAction(action, payload)
   │
   ├── POST /api/v1/dispatch  {action, payload, session_id}   ◄── main UI path (server-rendered HTML "regions")
   └── REST /api/v1/<feature>/…                                ◄── typed JSON API (js/api.js) for integrations/tests
                         │
                    FastAPI (backend/app/main.py)
                         │  GZip · CORS (restricted) · session cookie · rate of work serialised by _dispatch_lock
                         │
        ┌────────────────┴──────────────────┐
        │                                   │
 StarAppController (starapp/app.py)    REST routers (backend/app/features/*)
 one instance per browser tab/session   router → service → repository (parameterised SQL)
        │
 DataStore (starapp/storage.py)  ← ONE process-wide, in-memory, shared by all sessions
   • entity dicts + incrementally maintained secondary indexes
   • memoised aggregates keyed by a DB fingerprint
        │
 SQLite  data/starapp.db   (WAL, foreign_keys=ON, busy_timeout=5000, 30 extra performance indexes)
```

**Two execution modes of the same Python code**

1. **Server mode (default):** the controller runs in the FastAPI process; the browser receives HTML fragments.
2. **Offline/Pyodide mode:** `js/starapp_bundle.js` (generated by `scripts/pack_py.py`, 30 modules + `data/starapp.db` embedded as base64 → build it from a clean DB) embeds the same Python and runs it in the
   browser. Code detects it with the `IS_BROWSER` flag (`starapp/app.py`) and reads form fields from the DOM. The bundle endpoint
   `/js/starapp_bundle.js` is served only when `STARAPP_DEMO_MODE=true`. **Any change under `starapp/` requires rebuilding the bundle.**

## 2. Request lifecycle (UI path)

1. `bridge.js` calls `POST /api/v1/dispatch` with `X-Session-Id` (must match `_SESSION_ID_RE`; `default` allowed).
2. `main.py::dispatch_action` runs `_run_dispatch` in a **threadpool under a global lock** (actions share one in-memory store, so they are serialised).
3. `_run_dispatch` finds/creates the `StarAppController` in the **LRU registry** `_session_controllers` (cap `STARAPP_MAX_SESSIONS`, default 1500).
   If the session was evicted/restarted, state is restored from the **HMAC-signed snapshot** the browser sends back (`session_state`).
4. `controller.handle_event(action, payload_json)`:
   * gate: `action ∈ _GUARDIAN_ONLY_ACTIONS` and user not guardian ⇒ `ActionDenied` (logged `DENIED guardian-only action …`);
   * a big `if/elif action == "…"` chain mutates controller state and calls `store.*` writers; business rules raise `ActionDenied` or `set_flash(...)`;
   * `sync_badge_reviews` / `sync_mapping_requests` are the browser's live-sync polls (see §7 "Live sync"): the backend may answer `{"unchanged": true}`;
   * read-only cycles (closed) block mutations except `_CYCLE_READONLY_SAFE_ACTIONS`.
5. **One render per action**: `controller.render()` builds `regions` (sidebar, topbar, main viewport, modal) via `views_*`; HTML passes through
   `iconize_html` (emoji → SVG) and `humanize_internal_ids`.
6. Response: `{success, regions, full_html (only if no regions), current_view, session_state (signed), user}`. `bridge.js::updateRegions` patches the DOM in place.

**Auth for the UI path:** login is an action (`login` / `select_demo_account`). The controller verifies credentials, validates `selected_role`
against `user_role_assignments`, and sets `current_user`. Navigation actions (`nav_guardian`, `nav_cosmonaut`) validate the target view
(`_GUARDIAN_VIEWS` / `_COSMONAUT_VIEWS`) and role.

## 3. REST path (`/api/v1/*`)

Routers: auth, users, bands, badges, reviews, allotments, submissions, evaluations, audit, cycles, gemini. Dependencies in
`backend/app/core/dependencies.py`:

* `get_current_user` reads the `starapp_session` cookie (HttpOnly, SameSite, optional `Secure`), touches `last_active_at` at most every 5 min.
* `require_roles(...)` (fixed in Stage 1): role aliases, roles read from `user_role_assignments`, really denies.
* Header/query identity shortcuts (`X-User-Id`, `?role=`) are accepted **only in demo mode**.
* `cycles` router: all mutations are guardian-only and the actor comes from the session (never from the request body).
* `GET /api/health` → `{status, database:{integrity, foreign_key_violations, table_count}, version}`.

> Note: the REST service layer duplicates a smaller subset of the controller's rules (see backlog item "unify services"). The UI/controller path is the
> richer and authoritative implementation of the workflow.

## 4. The controller (`StarAppController`)

* Holds **per-session UI state** (current view, selections, filters, modal, flash, page numbers, mapping wizard state, selected cycle …).
* Constants worth knowing: `_GUARDIAN_VIEWS` (20 ids), `_COSMONAUT_VIEWS` (17 ids), `_GUARDIAN_ONLY_ACTIONS` (47 actions, incl. `open_revoke_decision_confirm` / `revoke_guardian_decision`), `_CYCLE_READONLY_SAFE_ACTIONS`.
* **Mapping-request lifecycle (24 h):** `send_mapping_requests` stamps `expires_at = sent_at + 24 h`; `handle_event` begins with `_expire_overdue_mapping_requests()` (→ `store.expire_overdue_mapping_requests`) which turns every unanswered, overdue request into `rejected` + `expired=True`, notifies reviewer and Guardian and logs an activity. Late accepts are refused; `resend_mapping_request` (Guardian-only) reopens with a fresh window; `sync_mapping_requests` is the no-op the browser calls when a countdown hits 0. Requests without `expires_at` (legacy seed) never expire.
* **Edit Badge save:** `execute_save_badge` routes an EXISTING badge to `_save_badge_allotment_edit` (cosmonaut list + `reviewer_assignments` + timeline only; writes band mappings, `badge_timelines` incl. `reviewer_id`/`review_window_json`, reviewer's request `cosmonaut_ids`, notification; deletes timelines of removed cosmonauts via `store.delete_timeline`). New badges still use the full creation path.
* **Review calendar:** `mapping_review_mode` ∈ `gap` (3/5/7… consecutive working days from the clicked day), `manual` (each click toggles one working day; weekends ignored; ≥ 1 day kept; max 45), `range` (legacy, server-only).
* `execute_*` methods hold the heavy workflows: `execute_save_badge`, `execute_submit_project`, `execute_submit_evaluation` (reviewer *and* guardian
  grading: the reviewer saves marks + a **recommendation** and the submission becomes `reviewer_assessed`; the Guardian's chosen option approves / requests re-attempt / rejects),
  **`execute_revoke_guardian_decision`** (Guardian-only undo of the saved decision), `execute_request_project` (legacy, no screen uses it), `execute_submit_extension_request`, `execute_extension_decision`, `execute_broadcast_announcement`, `execute_save_material/_bulk/update`.
* **Guards worth knowing:** `_allocated_project_denied(badge_id)` (single guard for the `open_allocated_project_page` action AND for rendering `c_project`: badge allotted to the user + their project sent), `_expire_overdue_mapping_requests`, `_expire_overdue_badge_reviews` (both run at the top of `handle_event`).
* Rendering: `render()` → `render_login_view()` or a role view, plus `render_active_modal()`.
* Lists use `set_list_page` + `starapp/pagination.py` (page state kept in a contextvar bound per request).

## 5. DataStore (`starapp/storage.py`)

* Process-wide singleton `store`. Loads from SQLite once (`load_from_json` is idempotent via `_loaded_data_version`), then serves reads from memory.
* **DB fingerprint** = `PRAGMA data_version` + `conn.total_changes`. Any write by *any* connection changes it; memoised aggregates and indexes are
  invalidated lazily by comparing fingerprints.
* `_memoized(key, builder, extra, scope="all"|"learning")` — cached derived data (cohort profiles, cycle performance, leaderboards). `mark_dirty(learning=False)`
  distinguishes feed-only writes (activity/notifications) from learning-data writes so heavy caches survive feed churn.
* **Secondary indexes** (`_ensure_ix` / `_ix_commit`) — e.g. timelines by cadet/reviewer, submissions by cadet+badge, assessments by submission — maintained
  incrementally on each write.
* **Lazy submission payloads:** `ProjectSubmission` loads PDF/code blobs on demand (`payload_is_lazy`, `_hydrate`, `export_to_dict(include_blobs=False)`).
* **Feed tables** (`activity_events`, `notifications`) sync by rowid watermark (`_sync_feed_tables`) instead of reloading.
* **Write failures:** `StorageWriteError` / `_write_failed`; on failure `resync_from_database()` rolls memory back to disk truth.
* Upserts use `INSERT … ON CONFLICT DO UPDATE` (never `INSERT OR REPLACE` — see README §2).

## 6. Database layer (`starapp/database.py`, `backend/app/database/`)

* PRAGMAs: `foreign_keys=ON`, `journal_mode=WAL`, `busy_timeout=5000`.
* `PERFORMANCE_INDEXES` (30) are created by `ensure_performance_indexes` on first start (in place, idempotent, no data change); `PRAGMA optimize` runs.
* `export_to_dict(include_blobs)` builds the in-memory snapshot with grouped queries (no N+1).
* `authorize_badge_decision` guards `approve_badge` / `return_badge`.
* Health: `check_database_integrity()` ignores `sqlite_%` internal tables (so `sqlite_stat1` doesn't change the table count).

## 7. Front end

* `index.html` loads `css/`, `js/bridge.js`, `js/api.js` (and the Pyodide bundle in offline mode).
* `bridge.js`: `dispatchAction`, `updateRegions`, and **`_sidebarSignature()`** — the sidebar is replaced only on a *structural* change; the
  active-link highlight is patched in place (`class="nav-link active"` is ignored in the signature). This removed the flicker. Don't regress it.
* **Sidebar:** the Guardian sidebar header shows **only the band chip** (`.sidebar-band-chip`, top-left; no brand / portal name / role pill; header hidden when no band is active). The Cosmonaut portal sidebar now matches: header = **only the band number** (`.sidebar-band-chip.is-link`, which also opens the cycle picker `c_choose_cycle`; the old brand / Learner pill / `C1 · ACTIVE` cycle pill are gone) and the **same footer as the Guardian sidebar**: the user's name card above two side-by-side buttons, View Profile + Sign Out - ONE shared renderer for every portal (`views_common.render_sidebar_actions_footer`; the old `render_sidebar_profile_footer` and `.lg-sidebar-signout-btn` were removed). In the 72 px rail the card is hidden and the buttons stack as icons; expanded they share one row. `.nav-link` uses `gap: 12px; padding: 0 11px 0 15px` so the longest label ("Reviewer Badge Approval", bolder when active) is not truncated at 256 px. A fixed 72 px rail that expands to 256 px on hover (or when pinned). The main area **shrinks with it** (`.app-sidebar:hover + .app-main` → `margin-left`/`width`, same easing; 90 ms hover-intent delay on enter so a sweeping mouse does not re-flow the page). At ≤ 1100 px wide the expanded rail overlays instead (rail stays reserved), ≤ 768 px uses the stacked top bar; `prefers-reduced-motion` disables the animation. Lists use container queries, so they re-layout to the new width.
* **Page title in the Back-button row:** `views_common.TITLE_HOIST_VIEWS` lists the views whose own first `<h1>/<h2>` is shown at the left of the top strip (`hoist_page_title` → `render_global_back_bar(title)`, `.app-strip-title`); the heading stays in the page as a visually hidden `.app-title-hoisted` element. Hero-style pages (dashboards, profile, cycle cards, band picker, roadmaps, pillar placeholders) keep their designed header — add a view to the set only if its heading is a plain title.
* **Type-ahead inputs:** use `StarAppBridge.debouncedDispatch(action, value)` (250 ms) for search boxes; responses of `search_*` / `filter_*` / `set_list_page` actions are ignored when a newer action or a pending keystroke supersedes them (prevents dropped characters).
* **bridge.js feature blocks (display only - the server validates everything):** `debouncedDispatch`; 24 h **countdown ticker** (`.rq-timer[data-remaining]`, ticks each second from the server-rendered seconds, calls `sync_mapping_requests` at 0); **glass date picker** (`openDatePicker(btn)`: `.gd-btn` + hidden ISO input, `data-gd-min` / `data-gd-pair`, flips above near the bottom, Esc/outside click closes; CSS in `liquid_glass.css`); **Edit Badge assignee helpers** (`addAssignee(id, rid)`, `removeAssignee`, `moveAssignee`, `clearAssignees`, `addAllShownAssignees`, `filterAssignMenu`, `toggleAssignMenu`, `collectReviewerAssignments`: every cosmonaut has ONE `.eb-person` row with a hidden `badge-assignee` checkbox + `data-rid`; rows not on the badge wait in `#eb-pool`); **decision list** (`setReviewDecision` drives the hidden `<select id="rubric-decision">`); `setMappingReviewDays` (calendar Days dropdown).
* **Modals** use `.modal-dialog` (`modal-lg`, `modal-xl`, `modal-cal`); wide ones (Timeline & Mapping, Edit Badge) lay out with **container queries** so they use the width they get.
* **Type scale & units:** tokens `--type-*` in `css/design_tokens.css`; all font sizes are rem; headings inside `.app-main` are pinned (h1/h2 2 rem [`--type-page-title`, was 1.75 until 2026-11-28], h3 1.25, h4 1 rem) in `components.css`.
* **Mobile shell (<= 768 px):** the sidebar becomes an off-canvas drawer (`css/responsive.css` section 11). `js/bridge.js` `initMobileMenu` creates `#starapp-mobile-bar` (hamburger `#starapp-menu-btn` + title) and `#starapp-menu-backdrop` once, outside the server-rendered regions (re-renders never touch them), and toggles the `m-nav-open` class on `<body>`; tapping a nav item / the band chip, the backdrop or Esc closes it, resizing above 768 px closes it. The bar and `.app-main` top padding show only when a sidebar exists (`body:has(.app-sidebar:not(.band-selection-hidden))`). 769-1100 px keeps the 72 px rail that overlays on hover. Verify with `python scripts/e2e_mobile_layout.py`.
* **Cache-busting:** `index.html` and `sw.js` reference assets as `…?v=N` (currently **121**, SW cache `starapp-runtime-cache-v78`); bump on every css/js change together with the asserts in `tests/test_backend_fullstack.py` and `tests/test_ui_remediation.py` (see README §2.6). `Report.md` / root `README.md` still show older values — `memory/` wins.
* **Live sync & no-flicker repaint:** `bridge.js::startLiveSync` re-dispatches `sync_badge_reviews` every 6 s while a page/popup with `data-live-sync` is open (single-flight, 4x back-off after 2 min idle, skipped in hidden tabs). `dispatchAction` treats every `sync_*` action as NOT a user action (no `localActionSeq` bump, stale answers dropped). The server (`backend/app/main.py`: `_LIVE_SYNC_ACTIONS`, `_regions_signature`) keeps the signature of the last regions sent to a session and answers `{"unchanged": true}` when only a countdown differs. Both sides compare HTML through a "stable" form — `views_common.stable_html_signature` (server) / `bridge.js::_stableHtml` (browser) blank `data-remaining="\d+"` and the `.rq-timer-text` clock — and `renderState.mainSig / modalSig` decide whether to repaint, so countdown ticks never repaint a page.
* **Perf rules for CSS (enforced by `tests/test_performance_and_live_sync.py`):** no `linear-gradient` on big glass surfaces (flat tints like `rgba(245,250,255,0.86)`), `backdrop-filter` only on chrome (sidebar, top bar, modal veil, popovers, login card), bounded animations (no endless animation on repeated elements), passive listeners, no `scroll` listeners. The countdown pill `.rq-timer` is `width: fit-content`.
* **Marksheet & review panels:** `views_common.render_standard_marksheet(marksheet, badge=None, all_attempts=None, tab_action=…)` is the single marksheet renderer (cosmonaut page `render_cosmonaut_results` + the `marksheet_modal`); `.ms-*` in `components.css`; `all_attempts` / `tab_action` are accepted for compatibility but ignored (one sheet). The reviewer panel (`views_cosmonaut.render_reviewer_assessment_detail`) and the Guardian panel (`views_guardian.render_guardian_review_detail`) are sized by `--rp-*` CSS variables per window-height tier (`.review-right-column`, see LOGICS K).
* **Times:** all user-visible timestamps go through `views_common.format_ist` / `ist_plain` / `to_ist` / `format_utc_stamp` (IST, UTC+5:30); stored values stay UTC ISO.
* **Connector geometry** (Assessment tree): the vertical line, elbow and dot hang off the same `<div>` (`.asm-tree-*-branch`, `.asm-elbow`), whole-pixel offsets from the card top, solid colours. Do not move the elbow onto the card `<button>` (browsers anchor abs-positioned children of buttons differently).
* Icons: views may contain emoji; `iconize_html` converts them to the SVG icon set in text nodes only. Prefer `get_icon("name")` directly in new code.
* Styling vocabulary: shared `btn-metal` / `btn-secondary`, glass cards, WCAG-AA text colours (700-weight hues). Minimum font size 10 px.

## 8. Security architecture (summary — details in RULES_AND_CRITERIA §7)

HMAC-signed expiring session snapshots (key `SECRET_KEY`) · session-id regex · LRU session cap · constant-time compare · restricted CORS ·
`STARAPP_DEMO_MODE` gating · central guardian-only action gate · REST RBAC fixed · login role validation · upload size cap (`MAX_UPLOAD_CHARS`, ~9 MB).

## 9. Scalability design (summary — details in LOGICS.md)

Measured at ~3,000 users on a synthetic DB: cold start 1.8 s / 94 MB, new session ~15 ms, Guardian dashboard ~300 ms, cadet pages ~9–200 ms,
~70 req/s with 60 concurrent users, 0 errors. **Current ceiling:** one process, actions serialised — fine for thousands of registered users with
modest concurrency; scale-out needs the backlog items (shared session store, uploads out of SQLite).
